# Week 8 Resources - Graph Theory

This week focuses on getting started with **graph theory** for competitive programming.

The goal is not to rush advanced graph algorithms. First become comfortable with graph representation, DFS, BFS, connected components, shortest paths basics, and standard CSES-style graph problems.

## Prerequisites

Before starting graphs, make sure you are comfortable with:

- Recursion
- Basic queues and stacks
- Vectors and adjacency lists
- Time complexity of `O(N + M)`
- Writing and debugging implementation-heavy code

After completing the relevant CSES graph problems:

- Use the Codeforces problemset tag: `graphs`

Do not jump to Codeforces graph problems before completing enough CSES practice.

## Suggested Approach

1. Watch the graph theory playlist topic by topic.
2. Read the graph section from the CSES handbook if you prefer text-based learning.
3. Implement every algorithm yourself.
4. Solve the relevant CSES graph problems.
5. Debug your own graph code patiently.
6. Prepare clean templates for DFS, BFS, connected components, shortest path, and topological sort.
7. Move to Codeforces `graphs` tag after CSES practice.

## General Tips for Graphs

- Write code every time. Do not only watch explanations.
- Debug the code yourself.
- Do not use AI for debugging graph code.
- This applies not only to graphs, but to every problem you solve.
- Prepare templates that you understand and can modify during contests.
- For DFS and BFS, know exactly what your visited array, parent array, distance array, or component array represents.

## Most Important Advice

Graphs are implementation-heavy in the beginning.

Do not memorize code blindly. For every graph problem, ask:

- What are the nodes?
- What are the edges?
- Is the graph directed or undirected?
- Is it weighted or unweighted?
- What should each traversal/state store?
- Why is DFS, BFS, shortest path, or another algorithm suitable here?

Once this thinking becomes natural, graph problems become much easier to approach.
